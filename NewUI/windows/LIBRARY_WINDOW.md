# Библиотечное окно

Единственный редактируемый источник настроек — `library_window.json`. `Library_Window.js` отвечает за представление; `assets/resource-library-v2.js` сохраняет владельца загрузки, пагинации, Lightbox и выбора. `Window.js` продолжает обслуживать зарегистрированные окна групп полей.

## Адреса файлов

Единый объект `window.BZNLibraryRuntimeConfig` создаётся в первом загрузочном блоке `index.html`, до подключения остальных скриптов. В этом одном месте находятся:

- общий `LIBRARY_STORAGE_HTTP_BASE_URL` и отдельные наследуемые базы `INTERFACE`, `CONTENT`, `API`;
- JS окна библиотеки, основной JS галереи, JSON/JS-конфигурация окна и CSS галереи;
- JS/CSS Lightbox;
- индекс готовых масок, каталог изображений масок и каталог сгенерированных data-скриптов;
- HTTP endpoint серверной библиотеки.

Чтобы перенести весь комплект без изменения структуры каталогов, достаточно заменить `LIBRARY_STORAGE_HTTP_BASE_URL`. Если интерфейс, контент и API находятся на разных серверах, меняются только три соответствующие base-переменные. Отдельный файл можно перенести изменением его пути в `LIBRARY_RUNTIME_PATHS`. Например, для каталога `https://design.bzn.ru/ui/masks/` задаётся content-base `https://design.bzn.ru/` и путь готовых масок `ui/masks/`.

Относительные значения продолжают работать в `file://` и на локальном HTTP. Внешние JSON, endpoint и применение картинки через `fetch` требуют CORS от сервера; простое отображение миниатюры не доказывает, что файл разрешено прочитать и сохранить.

### Распределённое хранение

`BZNLibraryRuntimeConfig.storage` разделяет серверы, URI-каталоги и построение конечного адреса. Публичные `images`, `masks` и `templates` имеют отдельные server-переменные, поэтому любой тип можно перенести на свой CDN. Скрипты каталога шаблонов и готовых масок также берутся из content URL, а не повторяются строками в основном списке загрузки.

Библиотеки не используют конфигурацию WebGPU. WebGPU остаётся отдельным вычислительным сервисом в `canvas-ui.data.js`; его endpoint не является сервером хранения и не участвует в построении библиотечных URL.

Пользовательское хранилище сейчас настроено так:

- `user_server` → `https://lk.bzn.ru/`;
- `users_folder` → `user_folders/`;
- `user_id_hash` → временный результат `get_user_hash()`, сейчас `test-user-hash`;
- коллекции → `templates/`, `images/`, `masks/`, `files/`.

Формула реализована одним `DistributedStorageUrlBuilder`: `server / users_folder / user_id_hash / collection / file_uri`. Например, `storage.fileUrl.user('images', 'img.webp')` возвращает `https://lk.bzn.ru/user_folders/test-user-hash/images/img.webp`. При подключении аккаунта меняется только тело `get_user_hash()`. Имена файлов кодируются по сегментам; `.` и `..` отклоняются, чтобы URI не мог выйти из пользовательского каталога.

## Настройки

- `layout`: сетка 6 × 5, карточка 112 × 92, фиксированное окно 738 × 646. Размер страницы вычисляется как `columns * rows`; отдельной копии `pageSize` у вызывающих нет. Неполная последняя страница не уменьшает окно.
- `tabs`: порядок, подписи и типы Images, masks, Stock, Lib, ComfyHistory, texts, styles.
- `profiles`: совместимость вкладок. `enabled` разрешает источник, `disabled` показывает недоступную вкладку, `hidden` убирает её из интерфейса. Недоступные для текущего runtime источники также disabled.
- `callers`: `contentType`, `activeTab`, ссылка на `profile`. Необязательный `tabs` точечно переопределяет профиль. Активная вкладка обязана быть совместимой и enabled.
- `libraryCallers`: совместимость прежних вызовов только с `library`; новые адаптеры передают явный `callerId` независимо от физического серверного ключа.

После изменения JSON выполнить `node NewUI/tools/build-library-window-config.mjs`. Файл `library_window.data.js` генерируется для file-mode, вручную не редактируется. HTTP читает JSON напрямую. Оба пути наследуют build/query-параметры основного скрипта. Проверка `Library_Window_Contract.test.mjs` сверяет их содержимое.

## Контракт вызова

`BZNResourceLibrary.open(options)` сохраняет прежние `library`, `provider`, `accept`, `shuffle`, `labels`, `onSelect`, `modalLock`. Добавлены:

- `callerId`: ключ из JSON. Для масок блока — `readyBoxMasks`, фона — `readyBackgroundMasks`, серверных изображений — `imageLibrary`.
- `callerContext`: переносимые данные вызывающего, например `{ layerId, newLayer }` или `{ layerId, targetKind }`. При открытии копируются и замораживаются, не читаются повторно из текущего selection.
- `contentType`: необязательная проверка соответствия JSON. Несовпадение отклоняется до замены текущего вызова.
- `sources`: необязательная карта дополнительных источников по tab ID. Источник содержит `library` и/или `provider`, может переопределить `accept`, `labels`, `shuffle`, `onSelect`. Остальные значения наследуются от исходного вызова, не от предыдущей вкладки. Несовместимые источники игнорируются. Без адаптера вкладка остаётся disabled, без фиктивных результатов.

Provider получает `{ page, pageSize, callerId, contentType, callerContext, tabId }`; прежние providers могут продолжать читать только первые два поля. Ответ остаётся `{ ok, items, page, pages, total }`. `onSelect(item, invocation)` дополнительно получает захваченный вызов; старые callback с одним аргументом продолжают работать. Явный `false` означает отказ от применения.

Переключение вкладки или новый вызов отменяет применение устаревшего ответа/предпросмотра. Галерея сначала закрывает принадлежащий ей Lightbox, затем свой modal lock. Маска также проверяет, что Painter всё ещё принадлежит исходным `layerId/targetKind`; сохранение остаётся в `loadReadyMaskItem -> loadFile -> save`.

При открытии снова выбирается вкладка текущего вызывающего, а не последняя чужая вкладка. ArrowLeft/ArrowRight/Home/End пропускают disabled и hidden. DOM окна, вкладок и общих кнопок один; обновляются состояние и содержимое страницы.

## Проверки

`Library_Window_Contract.test.mjs` — JSON/bridge, маршрутизация и адаптер. `Library_Window_Browser.mjs` — три Chrome-цикла на настоящем `index.html`, все готовые маски, 30/30/30/24, геометрия, вкладки, отмена устаревших callbacks и настоящее сохранение в исходный слой. `Library_Window_Http_Browser.mjs` — три локальных HTTP-цикла с тестовым endpoint, без заявления о работе production/PHP.
